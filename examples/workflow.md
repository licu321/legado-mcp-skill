# 示例：端到端工作流（workflow）

> 展示 AI 在“用户只启动 App”的前提下，完成 **新增书源 → 保存 → 调试 → 校验 → 交付** 的完整流程。
> 所有步骤均由 AI 通过 MCP 工具执行，用户只需提供初始信息与确认。

---

## 场景

用户说：*“我写了一个新的书源脚本，想加进阅读 App 并确认它能正常搜书，麻烦帮我弄一下。”*

## 第 0 步：连接（用户侧唯一动作）

AI 提示用户：**只需要启动 Legado App**，并：
1. 确认 **设置 → MCP 服务** 已打开；
2. 告知设备 IP 与令牌（或由用户从 App 通知栏读出）。

AI 配置客户端：`http://<设备IP>:1236/mcp` + 请求头 `X-Legado-Token: <令牌>`。

## 第 1 步：连通性探针（只读）

```
工具：list_sources
参数：（空）
```
返回：`共 41 条` 及摘要。→ 确认连接成功、令牌有效。

## 第 2 步：保存书源

用户把 JS 脚本（或 JSON）贴给 AI。

```
工具：save_source
参数：
  source: <用户提供的脚本/JSON>
  format: js            # 或 json；缺省会按首字符自动识别
```
返回：`已保存：<书名>书源\nbookSourceUrl: https://example.com`。

> 要点：重复保存保留启用/排序/权重；`format` 缺省自动识别（首字符 `{`/`[` → json，否则 js）。

## 第 3 步：调试书源（验证搜索）

```
工具：debug_source
参数：
  url: https://example.com          # 上一步返回的 bookSourceUrl
  key: 斗破苍穹                      # 用户想搜的关键词
  timeoutSec: 120
```
解读逐步日志：
- 若返回书籍列表 → 搜索正常，进入第 4 步。
- 若日志中出现 `404` / JS 异常 / 空结果 → 执行排错流程（见 `prompts/troubleshoot.md`），
  定位到规则或脚本问题后，用 `save_source` 修正再重试。

## 第 4 步：批量校验（可选，确认整体可用性）

```
工具：check_source
参数：
  urls: ["https://example.com", "<其他新源>"]
```
返回三段汇总（失败/通过/未完成）。对“失败”项回到第 3 步逐一定位。

## 第 5 步：交付结论

```
## 排查结论
- 根因：书源首次接入，无既有问题。
- 证据：debug_source 搜索关键词返回 n 条结果，耗时 x 秒。
- 修复建议：无需修改；已启用。
- 验证方式：可在 App 内直接搜索确认。
```

## 工作流中常见的“AI 应主动做”的细节

| 时机 | AI 动作 |
|------|---------|
| 保存前 | 先用 `list_sources` 确认是否已存在同名/同 URL 书源（避免覆盖） |
| 调试前 | 确认 `url` 与库中完全一致 |
| 调试超时 | 调大 `timeoutSec` 或缩小 `key` |
| 通道占用 | 串行等待，不并行调用 `debug_source`/`eval_js`/`check_source` |
| 结束 | 建议用户关闭 MCP 服务开关 |
