# Prompt: HTTP 日志（logs）

> 用途：**查看应用内的 HTTP 请求日志**，定位网络层问题（请求头/响应/状态码/耗时）。

## 工具调用

### 开启/关闭记录
```
工具：set_http_log_recording
参数：
  enabled（必填，布尔）：true 开启，false 关闭。设置会持久化，切换不清空已有记录。
```

### 读取摘要
```
工具：get_http_logs
参数：
  limit（可选，整数）：条数，默认 50。
```

### 读取单条详情
```
工具：get_http_log
参数：
  id（必填，整数）：get_http_logs 返回的记录 id。
```

## 行为说明（来自官方实现）

- 日志仅写入**内存**，最多保留最近 **50 条**；App 重启后清空。
- 每条记录：请求/响应**正文单次最多 8 KiB**，超出截断。
- 写入时**自动脱敏**认证信息、Cookie 和常见密钥字段。
- 未开启记录时，`get_http_logs` 会提示“HTTP 日志记录未开启”，但仍可能显示关闭前保留的记录。
- 摘要行格式示例：
  ```
  #12 2026-08-15T10:30:00Z GET https://example.com/api -> 200 123ms
  ```
  含 id、时间、方法、URL、状态码、耗时、可选错误。

## 使用流程（关键：先开记录，再复现）

1. `set_http_log_recording(true)` 开启记录。
2. 让用户（或通过 `debug_source`）**复现**问题请求。
3. `get_http_logs` 看摘要，定位可疑记录。
4. `get_http_log` 取该条详情，检查请求头/正文/响应。
5. 排查完成可 `set_http_log_recording(false)` 关闭。

## 常见错误

| 信号 | 含义 | 处置 |
|------|------|------|
| 列表为空 | 未开启记录，或尚无请求 | 先开启记录再复现 |
| 找不到想要的那条 | 内存只保留 50 条 | 尽快读取；必要时缩小复现范围 |
| 详情被截断 | 正文超 8 KiB | 聚焦关键请求头与状态码 |

## 注意（安全）

- 日志虽已脱敏，但完整记录仍可能包含敏感业务数据；只在可信会话使用。
- HTTP 日志与 MCP 一样受令牌保护（令牌保护开启时）。
