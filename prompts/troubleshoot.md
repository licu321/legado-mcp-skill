# Prompt: 报错驱动自动调试（troubleshoot）

> 核心流程。当用户提供**错误文本、日志、截图转写**时，AI 必须严格按本节执行。
> 目标：把“用户手抄报错”变成“AI 自动定位 + 修复 + 验证”。

---

## 0. 铁律

1. **用户只需要启动 Legado App**。连接、认证、工具调用、排错全部由 AI 完成。
2. 收到错误后**先分类，再动手**；不要漫无目的地调用工具。
3. 每一步只调用**最小必要工具**（优先只读），避免误改应用状态。
4. 多轮排查：每轮“调用工具 → 解读 → 收窄假设”，直到根因明确。
5. 必须输出可验证的结论：根因、证据、修复建议、验证方式。

---

## 1. 流程总览

```
用户输入（错误文本 / 日志 / 截图转写）
        │
        ▼
┌─ 第 1 步：分类错误 ─────────────────────┐
│  对照下方分类表，归入最匹配的一类；      │
│  无法归类时，先收集最少必要信息：        │
│  (a) 涉及的 bookSourceUrl                │
│  (b) 完整错误原文 / 日志                 │
│  (c) 复现步骤                            │
└──────────────────────────────────────────┘
        │
        ▼
┌─ 第 2 步：选择最小必要工具 ─────────────┐
│  按分类表“最小工具序列”只取第一步。      │
│  默认从只读工具开始。                    │
└──────────────────────────────────────────┘
        │
        ▼
┌─ 第 3 步：多轮排查（循环） ─────────────┐
│  调用工具 → 解读返回 → 更新假设           │
│  → 收敛范围 → 重复，最多 5 轮            │
│  每轮后判断：根因是否已明确？             │
│  是 → 进入第 4 步；否 → 换/加工具再查。   │
└──────────────────────────────────────────┘
        │
        ▼
┌─ 第 4 步：输出结论 ──────────────────────┐
│  根因 │ 证据 │ 修复建议 │ 验证方式        │
└──────────────────────────────────────────┘
```

## 2. 错误分类表（第 1 步依据）

| # | 类别 | 典型信号（来自实现/日志） | 最小工具序列 |
|---|------|---------------------------|--------------|
| E1 | 认证失败 | HTTP `401`；“MCP 访问令牌未配置或不正确”；`X-Legado-Token` 缺失/错误 | 核对令牌 → 重试 `list_sources` |
| E2 | 连接失败 | `Connection refused` / 超时 / 无法到达 `http://<IP>:1236/mcp`；Host/Origin 拒绝 | 检查服务开关、同局域网、端口 → 重试 |
| E3 | 未找到书源 | “未找到书源，请检查书源地址”；“未找到书源：<url>” | `list_sources` → `get_source` |
| E4 | 调试通道占用 | “调试通道占用中，请稍后重试” | 等待 → 重试 |
| E5 | 调试/求值超时 | `[调试超时 Xs…]`、`求值超时 Xs，脚本已取消` | 调大 `timeoutSec` → 重试 |
| E6 | JS 错误 | `-- 错误 --` + 异常堆栈 / `java.log` 报错 | `get_source` → `eval_js` 分步 → `debug_source` |
| E7 | Cookie 异常 | “该域名没有 Cookie”；“必须包含有效的 name=value”；登录态失效 | `get_cookies` → `set_cookie` → 复测 |
| E8 | 批量校验未完成 | `[未完成]` / `NOT_COMPLETED`；“校验服务未能启动” | 前台确认 → `check_source` 重试 |
| E9 | HTTP 日志异常 | 列表为空；“HTTP 日志记录未开启”；详情截断 | `set_http_log_recording(true)` → 复现 → `get_http_logs` |
| E10 | 未知/混合 | 无法归入以上 | 收集 3 项信息 → 从 `list_sources` + `get_source` 起步 |

## 3. 各类别的详细处置（第 2、3 步）

### E1 认证失败（401）
1. 确认令牌保护状态：默认开启；开启时**所有** MCP 请求必须带 `X-Legado-Token`。
2. 核对令牌与 App“设置 → 其他设置 → Web 与 MCP 访问令牌”**完全一致**。
3. 令牌不会进入备份，换设备/恢复后需重新配置。
4. 重试 `list_sources`。仍 401 → 请用户重新配置令牌 → 重启 MCP 服务。

### E2 连接失败
逐项排查（可一次并行确认，但一次只发一个连接探测）：
1. “MCP 服务”开关是否打开（App 通知栏可见服务地址）。
2. 设备 IP 是否变化（切 WiFi/热点后变化；以通知栏为准）。
3. 端口是否默认 `1236`（App 内可改，合法范围 1024..65530）。
4. 是否同一局域网、防火墙是否放行。
5. 重试连接；失败则请用户**重启 MCP 服务开关**后重试。

### E3 未找到书源
- 原因：传入的 `bookSourceUrl` 与库中记录不一致（常见：大小写、尾部斜杠、协议 http/https）。
- 处置：`list_sources`（带关键词）找到准确 URL → 用准确值重试 `get_source` / `debug_source` / `delete_sources`。

### E4 调试通道占用
- 原因：`debug_source` / `eval_js` / `check_source` **共用同一通道**，或 App 内正在调试/校验。
- 处置：**不要并行调用**这三个工具；等待前一个完成（一般秒级），再重试。

### E5 调试/求值超时
- 原因：源响应慢、卡住，或默认超时偏短（`debug_source` 默认 120s / `eval_js` 默认 60s）。
- 处置：
  1. 增大 `timeoutSec`（`debug_source` 上限 600，`eval_js` 上限 600）。
  2. 用更小的 `key` 缩小范围（如直接对具体 URL 而非全站关键词）。
  3. 若仍超时，转向 HTTP 日志（E9）看请求是否真正发出/返回。

### E6 JS 错误
1. `get_source` 检查脚本语法与引用（是否缺函数、变量名错）。
2. `eval_js` 分步验证：先跑最小脚本确认环境，再逐段跑出错逻辑。
   - 注意：`eval_js` 不自动执行书源 `mainJs`；绑定 `url` 只提供运行时身份。
   - 脚本上限 1 MiB；超限报“脚本不能超过 1 MiB”。
3. 用 `debug_source` 看逐步日志中的实际报错位置。
4. 依据错误定位（如 `java.log` 输出的异常栈）给出修复。

### E7 Cookie 异常
1. `get_cookies` 查看当前 Cookie（持久+会话合并）。
2. 与登录所需字段比对，缺失/过期则 `set_cookie` 补写（分号分隔 `name=value`，合并写持久层）。
3. `clear_cookies` 会同时清持久/会话/WebView（不可恢复）——仅确认要重置登录态时使用。
4. 修改后 `debug_source` 复测登录态。

### E8 批量校验未完成
- “未完成”≠失败：可能因为校验期间书源被删除/重新保存，或结果快照缺失。
- “校验服务未能启动，请将应用置于前台后重试”：需 App 在前台。
- 处置：确认 App 前台 → 重新 `check_source`；分批（≤50）降低波动；避免校验与 `debug_source` 并发。
- 客户端取消不会中止应用内校验；停止请在 App 校验通知中操作。

### E9 HTTP 日志异常
1. 先 `set_http_log_recording(true)`（未开启时 `get_http_logs` 会提示）。
2. 让用户复现问题（或通过 `debug_source` 触发）。
3. `get_http_logs` 看摘要 → `get_http_log` 看详情（正文上限各 8 KiB）。
4. 定位：状态码、耗时、请求头/响应差异。

### E10 未知/混合
1. 收集：书源 URL + 完整错误原文 + 复现步骤。
2. 从只读起步：`list_sources` → `get_source` → 若涉及网络再 `get_http_logs`。
3. 每轮向用户确认关键假设，避免误判。

## 4. 输出结论格式（第 4 步固定模板）

```
## 排查结论
- 根因：<一句话，如：书源 searchUrl 未对特殊字符 URL 编码，导致关键词含中文时 400>
- 证据：<工具返回的关键片段，如 debug_source 日志第 N 行报 400 Bad Request>
- 修复建议：<具体到字段/脚本，如：对 key 参数做 encodeURIComponent，或改用 POST>
- 验证方式：<用哪个工具怎么复验，如：保存后用 debug_source 以同一关键词重跑，应返回结果列表>
```

## 5. 常见错误速查卡（一张表覆盖要求的所有类别）

| 你看到的 | 原因 | 第一动作 |
|----------|------|----------|
| `401` / 令牌未配置或不正确 | 令牌错误/缺失/保护开启 | 核对 `X-Legado-Token` |
| 连接失败 / 拒绝连接 / 超时 | 服务未开 / IP 变 / 端口错 / 非同网 | 查服务开关与 IP，重试 |
| 未找到书源，请检查书源地址 | `bookSourceUrl` 不匹配 | `list_sources` 取准确值 |
| 调试通道占用中，请稍后重试 | 通道被另一任务占用 | 等待后重试（勿并行） |
| 调试超时 / 求值超时 | 慢源或超时太短 | 调大 `timeoutSec` |
| `-- 错误 --` + JS 异常 | 脚本运行错误 | `get_source` → `eval_js` 分步 |
| 该域名没有 Cookie | 未登录或无 Cookie | 登录/复现后重读 |
| `[未完成]` / 校验服务未能启动 | 校验会话问题 / App 未前台 | 前台 + 重试 `check_source` |
| HTTP 日志记录未开启 | 未开记录开关 | `set_http_log_recording(true)` |
| 脚本不能超过 1 MiB | `eval_js`/`save_source` 超限 | 精简脚本 |

## 6. 安全红线（贯穿全程）

- 只读优先；写操作（`save_source` / `set_cookie` / `clear_cookies` / `delete_sources`）需确认后再执行。
- `debug_source` 输出、`eval_js` 结果、`get_cookies` 均**不脱敏**，包含敏感信息，勿外泄。
- 仅可信局域网使用；任务结束建议关闭 MCP 服务。
