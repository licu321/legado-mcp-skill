# Prompt: 调试书源（debug_source）

> 用途：**运行应用内书源调试，返回逐步日志**，是定位书源运行时问题的核心工具。

## 工具调用

```
工具：debug_source
参数：
  url（必填）：书源 bookSourceUrl（先经 list_sources 确认）。
  key（必填）：调试关键词或入口 URL。
  timeoutSec（可选）：超时秒数，默认 120，范围 10..600。
```

## key 的语义（来自官方实现）

| key 形式 | 含义 |
|----------|------|
| `关键词` | 按关键词触发搜索调试 |
| `绝对 URL` | 直接对该 URL 发起调试 |
| `::URL` / `++URL` / `--URL` | 带前导标记的入口 URL（对应应用内调试入口的快捷方式） |

## 使用流程

1. 先 `list_sources` 拿到准确 `url`。
2. 用最能复现问题的 `key` 调用 `debug_source`。
3. 解读逐步日志，定位失败步骤（请求发送、响应解析、规则匹配、JS 异常等）。
4. 根据结论修改书源（`save_source`）后**再次调试验证**。

## 返回解读

- 返回**有界的逐步调试日志**（完整日志在结果中返回，不受通知超时影响）。
- 若超时：末尾追加 `[调试超时 Xs，以上为已收到的部分日志]`，可调大 `timeoutSec` 重试。
- 调试期间会发送 `notifications/message`；请求 `_meta.progressToken` 时同步发送 `notifications/progress`。
  通知超时或客户端不支持不影响最终结果。

## 常见错误

| 信号 | 含义 | 处置 |
|------|------|------|
| “调试通道占用中，请稍后重试” | 另一调试/校验/`eval_js` 正在进行 | 等待其结束再重试 |
| “未找到书源，请检查书源地址” | `url` 不匹配 | 重新 `list_sources` |
| 调试超时 | 源响应慢或卡住 | 提高 `timeoutSec`；或换更小的 `key` 缩小范围 |
| 输出含 JS 异常 | 脚本运行错误 | 结合 `get_source` 检查脚本，用 `eval_js` 分步验证 |

## 注意（安全）

- `debug_source` 输出**不脱敏**：可能包含请求参数、书源正文、Cookie 等敏感内容，只在可信会话中处理。
- 调试与 `eval_js`、`check_source` **共用同一通道**，串行执行，勿并行。
