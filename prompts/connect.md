# Prompt: 连接与认证（connect）

> 目标：**在用户只启动 Legado 阅读 App 的前提下，由 AI 完成全部连接、认证与连通性验证。**

## 1. 用户侧唯一需要做的事

1. 启动 **Legado 阅读 App**。
2. 进入 **设置 → 其他设置 → Web 与 MCP 访问令牌**，确认已配置令牌（令牌保护默认开启）。
3. 打开 **设置 → MCP 服务** 开关（App 内描述为“书源开发工具”）。
4. 确认运行 MCP 的电脑与手机在**同一可信局域网**。

> 如果用户不清楚设备 IP 或令牌：提醒用户查看 App 通知栏中 MCP 服务的常驻通知，其中会显示服务地址
> （形如 `http://192.168.x.x:1236/mcp`）；令牌在“Web 与 MCP 访问令牌”设置项中。

## 2. AI 自动执行：探测 → 配置 → 验证

### 步骤 A：收集连接信息
向用户索要（或引导其从 App 通知栏读出）：
- 设备 IP（如 `192.168.1.100`）
- 访问令牌（`X-Legado-Token` 的值）

若用户不知道令牌，让其先在 App 中配置，再提供。**令牌不进入应用备份**，恢复或更换设备后需重新配置。

### 步骤 B：配置 MCP 客户端
统一使用以下端点与请求头（Streamable HTTP）：

```json
{
  "url": "http://<设备IP>:1236/mcp",
  "headers": {
    "X-Legado-Token": "<令牌>"
  }
}
```

注意：
- 端口默认 `1236`；若用户在 App 内改过端口，使用其实际端口（有效范围 1024..65530）。
- 若用户关闭了令牌保护，`X-Legado-Token` 可省略；但**仅限可信网络**。
- 端点不做浏览器 CORS 预检，客户端需能自定义请求头（MCP 桌面客户端均满足）。

### 步骤 C：验证连通性
1. 调用只读工具 `list_sources`（空参数）作为连通性探针。
2. 成功 → 记录已连接的书源数量，进入下一步任务。
3. 失败 → 见下方错误处理。

## 3. 错误处理

### 401 Unauthorized
- 信号：HTTP 401、返回“MCP 访问令牌未配置或不正确”。
- 处置：检查令牌是否与 App“Web 与 MCP 访问令牌”中的值**完全一致**（含大小写与空白）；
  令牌保护是否开启（开启时缺令牌必 401）；然后重试 `list_sources`。

### 连接失败 / 拒绝连接 / 超时
- 信号：`Connection refused`、`ECONNREFUSED`、`timeout`、无法到达 `http://<IP>:1236/mcp`。
- 处置（按序）：
  1. 确认 App 的“MCP 服务”开关已打开（通知栏可见服务地址）。
  2. 确认设备 IP 正确且未变化（手机切 WiFi/热点后 IP 会变）。
  3. 确认端口正确（默认 1236）。
  4. 确认在同一局域网、防火墙未拦截 1236 端口。
  5. 重试。若仍失败，引导用户重启 MCP 服务开关。

### Host/Origin 拒绝
- 信号：服务端拒绝非本机/非当前局域网地址的请求。
- 处置：确认电脑与手机在同一局域网；MCP 只允许 `localhost`、`127.0.0.1`、`[::1]` 与设备当前局域网 IP。

## 4. 连接成功后的约定

- 向用户报告：已连接 `<设备IP>:1236`，可用 13 个工具。
- 后续所有书源操作前，**先用 `list_sources` 拿到准确 `bookSourceUrl`**。
- 全程不要把令牌打印到不受信任的外部服务。
