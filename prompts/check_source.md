# Prompt: 批量校验书源（check_source）

> 用途：**按应用当前校验配置批量校验书源**，并写回分组、错误备注与响应时间。

## 工具调用

```
工具：check_source
参数：
  urls（必填）：bookSourceUrl 数组，单批最多 50 个（自动去重、忽略空串）。
```

## 使用场景

- 用户报“某批书源失效/慢”，需要批量验证可用性。
- 新增/修改多个书源后统一校验。
- 用校验结果做筛选：失败项进入 `debug_source` 逐一定位。

## 行为说明（来自官方实现，重要）

- 复用应用内**校验配置**（与 App 手动校验一致），结果写回书源的**分组、错误备注、响应时间**。
- 返回格式为三段汇总：
  ```
  失败 n/N:
  [失败] 名称(url):错误详情
  通过 n/N:
  [通过] 名称(url):...
  未完成 n/N:
  [未完成] 名称(url):...
  ```
- **校验期间调试不可用**（与 `debug_source`/`eval_js` 共用通道，串行执行）。
- 客户端取消请求**不会中止**已启动的应用内校验；如需停止，请在 App 的校验通知中手动停止。
- 校验期间若书源被删除或重新保存，该项会标记为“未完成”，旧结果不会覆盖新记录。
- 校验服务启动有 5 秒等待；若未能启动会返回“校验服务未能启动，请将应用置于前台后重试”。
- 每个书源有明确结果后发送 `notifications/message`；请求 `_meta.progressToken` 时同步进度通知。

## 常见错误

| 信号 | 含义 | 处置 |
|------|------|------|
| 参数 urls 不能为空 | 漏传/空数组 | 补传有效 URL |
| 单批最多校验 50 个书源 | 超出上限 | 分批调用 |
| “未找到书源：<url>” | 存在无效 URL | 先 `list_sources` 过滤 |
| “调试通道占用中，请稍后重试” | 有调试/校验在跑 | 等待后重试 |
| “校验服务未能启动，请将应用置于前台后重试” | 校验服务未拉起 | 让用户将 App 切到前台后重试 |
| `[未完成]` | 书源被删/重存，或结果快照缺失 | 重新校验该批 |

## 注意事项

- 校验是**重操作且会写回书源元数据**：排查阶段先小批量，确认后再扩大。
- “未完成”不等于“失败”，需结合上下文判断（可能是并发修改导致）。
