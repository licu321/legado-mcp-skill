# Prompt: 读取单个书源（get_source）

> 用途：**读取一个书源的完整 JSON 定义**，用于检查规则、脚本或排查问题。

## 工具调用

```
工具：get_source
参数：
  url（必填）：书源的 bookSourceUrl（必须先经 list_sources 确认）。
```

## 使用场景

- 查看书源规则（搜索/发现/详情/目录/正文规则、请求头、代理、JS 脚本）。
- 排查书源“为什么解析不出来”前的静态检查。
- 保存前对比旧配置、检查要修改的字段。
- 在 `debug_source` / `eval_js` 之前确认脚本内容。

## 返回解读

- 返回该书源的完整 JSON（美化排版）。
- 超长内容最多返回 **200000 字符**，超出部分提示截断；必要时分段关注关键字段（如 `ruleSearch`、
  `ruleBookInfo`、`ruleToc`、`ruleContent`、`loginUrl`、`bookSourceUrl`）。

## 常见错误

| 信号 | 含义 | 处置 |
|------|------|------|
| “未找到书源，请检查书源地址” | 传入的 `url` 与库中不匹配 | 重新 `list_sources` 取准确 URL |
| 参数 url 不能为空 | 漏传参数 | 补传 |

## 注意

- 书源全文可能包含敏感业务数据（登录地址、Cookie 字段、自定义请求头）；只在可信会话中使用，勿外泄。
- 只读操作，不会修改应用状态。
